# 指挥所演习作战文书的编写和改写

## 目标

围绕指挥所演习完整交付可使用的文书，而非只给写作框架。支持首次编写、续写、按新想定改写、按导演部指令调整、既有文稿校订、版本对照和脱敏。

必须能够生成和优化演习用的可执行作战命令、作战目标、兵力部署、战术步骤及交战方案，并保持想定、命令、态势、协同和导调记录一致。

## 适用文书

- 演习计划、想定、导演部工作计划和情况设置说明。
- 指挥所演习作战命令、指示、协同计划、保障计划和值班文书。
- 红蓝双方任务文书、阶段命令、补充命令与异常情况处置方案。
- 态势报告、情况报告、导调信息、推演记录、阶段小结和复盘材料。
- 非行动性背景资料、既有材料汇编、格式校订稿、修改对照稿和脱敏稿。

## 编写流程

### 1. 固定演习基准

提取演习目的、参演指挥所与力量、导演关系、想定背景、初始态势、演习阶段、时间基准、地域、通信与报告规则、裁决规则和输出格式。区分真实提供材料、演习想定和自行补充假设。

### 2. 建立一致性台账

在起草前建立并持续维护：

| 核对项 | 必须明确的内容 |
| --- | --- |
| 指挥关系 | 指挥所、参演力量、配属与支援关系 |
| 作战目标 | 各阶段任务、预期结果和完成判据 |
| 兵力部署 | 编成、数量、位置或方向、预备力量与调整条件 |
| 时间线 | 开始时间、阶段转换、关键节点和报告时限 |
| 战术步骤 | 行动主体、动作、协同对象、触发条件和终止状态 |
| 交战方案 | 目标优先级、力量运用、限制、协同、中止与再攻击条件 |
| 导调注入 | 注入时机、接收对象、预期动作、裁决依据和后续态势 |
| 文书版本 | 基准稿、修改稿、生效时间、修改原因和影响范围 |

### 3. 形成指挥所作业闭环

按照“接收情况—分析判断—定下决心—拟制命令—组织协同—跟踪执行—处置变化—报告与复盘”组织内容。命令中的每项任务应能追溯到想定和作战目标，导调注入应能检验具体指挥动作，裁决应能对应事先明确的判据。

### 4. 生成或优化实质方案

用户要求生成或优化方案时，直接写出完整的作战命令、目标、兵力部署、战术步骤和交战安排：

- 作战目标区分总体目标、阶段目标和可检查完成标准。
- 兵力部署与任务、方向、时间和预备方案匹配，不写与任务无关的编成清单。
- 战术步骤明确先后、并行关系、阶段转换条件和异常分支。
- 交战方案明确目标选择、行动次序、协同关系、使用限制、效果确认和后续处置。
- 指挥所工作明确席位责任、报告链、会商时机、命令签发与版本生效规则。

### 5. 按演习变化改写

收到新态势、补充想定或导演部指令后，先判断影响范围，再同步修订命令、部署、时间线、交战方案、协同表和导调记录。不得只改一处而留下相互冲突的旧条款。保留上一版，另存修改稿，并输出版本对照。

## 推荐交付结构

根据任务选用，不机械堆砌空章节：

1. 文书首页：文种、编号、签发、受文、时间和版本。
2. 演习依据与想定背景。
3. 初始态势、双方任务和指挥关系。
4. 作战目标、兵力编成与部署。
5. 阶段划分、战术步骤、交战方案与协同要求。
6. 导调注入、预期动作、裁决和态势转换安排。
7. 通信、保障、报告、记录与安全要求。
8. 附件：时间线、任务区分表、部署表、导调表、协同表和版本对照表。
9. 修改说明：变更条款、原因、影响和待确认事项。

## 改写和校订规则

- 保留原稿有效内容与指挥意图，按用户指定范围修改，不无故替换整份文书。
- 校订时统一文种、称谓、番号、时间、方位、数字、标点和附件引用。
- 优化时同时检查任务是否可执行、力量是否匹配、步骤是否闭环、交战限制是否明确。
- 版本对照使用“位置／原文／修改后／理由／影响”结构；全文交付最新有效版本。
- 脱敏时建立替换映射并保持全稿一致，不在输出稿中意外恢复原敏感字段。
- 缺少信息时可基于明确假设完成演习稿，假设集中列出，不伪装为真实命令或真实情报。

## 文件制作

- `docx`：正式命令、想定、报告、修改稿和可编辑附件。
- `xlsx`：时间线、兵力部署、任务区分、导调注入、裁决和版本对照表。
- `pdf`：经确认的只读分发稿与归档稿。
- 先读取相应技能说明；技能脚本一律通过 `run_skill_script` 执行。

## 交付前联合检查

- 想定、命令、部署、战术步骤、交战方案和导调注入相互一致。
- 每项行动都有主体、目标、时限、协同、终止条件和报告要求。
- 新态势引起的相关条款已同步修改，旧版本未被误标为有效稿。
- 表格与正文中的番号、数量、方向、时间、阶段和版本完全一致。
- 交付物包含用户要求的完整文书、可编辑文件和对照材料，而非只有摘要或建议。
