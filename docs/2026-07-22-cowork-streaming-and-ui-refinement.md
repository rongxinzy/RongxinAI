## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 日期 | 2026-07-22 |
| 目标分支 | `main` |
| 功能分支 | `codex/cowork-streaming-and-ui-refinement` |

| 影响范围 | Work 模式、Chat 模式、技能管理、引擎启动提示 |

## 2. 背景与目标

本次变更集中处理近期人工体验测试中发现的四类问题：

1. 跨会话、跨项目切换时，主界面会短暂显示新建任务页或旧会话内容；历史消息加载完成后，还可能先显示顶部，再跳到末尾。
2. 思考、工具调用和中间回答混合输出时，消息更新可能互相覆盖；思考尚未结束时正文提前出现，最终回答开始后中间过程的折叠规则也不稳定。
3. 固定速度的打字机效果在上游更新较快时会产生积压，Markdown 新行出现后还可能因整段重复解析而发生视觉抖动。
4. 引擎启动提示和技能管理页面存在交互、溢出及固定分页方面的细节问题。

本次目标是在不改变主进程与渲染进程隔离边界的前提下，建立明确的会话加载态和最终回答语义，减少无效重渲染，并统一相关界面行为。

## 3. 变更概览

### 3.1 引擎启动提示

- 启动或编译阶段继续显示顶部浮层，不阻塞主界面操作。
- 增加收起按钮，收起后仅保留图标和进度条；点击紧凑组件可恢复完整提示。
- 启动完成后延迟短暂隐藏，避免状态切换造成闪烁。
- 错误状态保持完整展开，并保留重试入口，避免错误信息被收起后难以发现。
- 复用现有 `Button`、`Progress`、`Tooltip` 与 Lucide 图标，样式遵循 `DESIGN.md`。

### 3.2 技能管理与技能市场

- 删除技能市场说明区下方多余的视觉分隔线。
- 技能市场改为分页承载单页内容，市场页容器本身不再出现纵向滚动条。
- 根据实际容器高度逐行收缩单页数量，确保分页区与卡片保持在可见区域内。
- 安装按钮统一依据 `installSource` 判断可安装性，避免只有展示来源、却缺少安装入口的情况。
- 已安装状态、安装中状态和可安装状态继续保持互斥。
- 技能详情弹窗改为固定头部、可滚动正文和固定底部操作区。
- 描述、来源、作者和 URL 均允许安全换行，长文本不再溢出弹窗背景。

### 3.3 会话切换与初始定位

- 新增 `loadingSessionId`，将“正在加载哪个会话”作为 Redux 中的显式状态。
- 点击历史会话时通过同步提交加载态，先呈现局部加载界面，再执行代理、项目和会话切换。
- 跨项目切换支持保留当前会话加载态，避免项目切换过程把界面重置为新建任务页。
- 加载结束时按会话 ID 清理状态，较早请求完成不会错误清除较新的加载请求。
- 会话内容由 `CoworkSessionViewport` 统一决定显示加载态、会话详情或空状态。
- 历史会话首次呈现时直接定位到末尾；会话内容在初始定位完成前保持不可见，避免先看到顶部再跳到底部。
- 对话容器初始滚动行为设置为即时定位，后续正常流式跟随仍使用原有滚动逻辑。

### 3.4 按会话隔离流状态

- 沿用最新 `main` 的 `streamingSessionIds` 和 `streamingSessions` 状态模型。
- `selectIsStreaming` 只判断当前会话是否位于 `streamingSessionIds` 中，不恢复旧的全局布尔值。
- 新建与继续会话分别使用按会话 ID 管理的进行中集合，切换到其他会话不会被全局锁误阻塞。
- Chat 模式的取消控制器同样按会话 ID 保存，停止一个会话不会中断其他会话。
- 清空当前会话时不清空其他会话的流状态；跨项目切换可选择保留会话加载态。

## 4. 流式输出设计

### 4.1 消息更新批处理

旧实现每帧只保存一条待处理更新。当思考消息和正文消息在同一帧内先后完成时，后一条更新可能覆盖前一条，造成思考文本截断或完成元数据丢失。

新实现使用 `RafMessageUpdateBatcher`：

- 以 `sessionId + messageId` 为键保存每条消息的最新快照。
- 同一消息在一帧内只提交最后一次更新，减少重复渲染。
- 不同消息即使在同一帧完成，也会分别提交，互不覆盖。
- 完成、取消或组件卸载时可单独丢弃消息缓存或释放整个批处理器。

该缓存只保存尚未提交到 Redux 的最新消息快照，生命周期最多一个动画帧，不承担会话历史持久化职责。

### 4.2 思考与正文的时序

对于带独立思考段的运行时，遵循以下顺序：

1. 收到思考开始或思考增量后，标记当前思考段处于打开状态并开始计时。
2. 思考段打开期间收到的正文快照先暂存，不立即呈现。
3. 收到思考结束事件后，完成当前思考计时，再释放暂存正文。
4. 每个中间正文在最终正文出现前保持可见，不因后续思考或工具调用提前折叠。
5. 只有整个代理运行结束时，最后一个有效正文才被提升为最终回答。

同时删除“正文为空时复制思考内容作为正文”的兜底逻辑，避免同一段思考被重复显示为中间回答。

### 4.3 最终回答语义

消息元数据新增两个字段：

| 字段 | 含义 |
| --- | --- |
| `isFinalAnswer` | 仅标记一次完整运行中面向用户的最终正文 |
| `thinkingDurationMs` | 当前思考消息由运行时测得的累计耗时 |

状态约束如下：

- 中间回答可设置 `isFinal: true`，但不得设置 `isFinalAnswer`。
- 正常完成时，最后一个有效正文设置 `isFinalAnswer: true`。
- 取消、空闲或错误结束时，不得把现有正文标记为最终回答。
- 每条思考消息使用独立计时结果，避免多个“已思考 X 秒”显示同一个持续增长的全局时间。
- 最终同步历史消息时同时写入存储并发送带元数据的更新，避免刷新前后语义不一致。

### 4.4 中间过程与执行摘要

最终回答出现前：

- 当前思考或工具动作以次级摘要显示。
- 摘要文字使用 Shimmer 效果。
- 工具动作尽量携带目标信息，例如正在读取文件、正在搜索内容或正在执行命令。
- 所有中间回答保持直接可见。

最终回答出现后：

- 思考、工具调用和中间回答统一收进全局执行摘要。
- 摘要默认折叠，最终回答保持直接可见。
- 摘要按实际数量显示“已完成 X 次思考、Y 次工具调用”；数量为零的类别不显示。
- 展开摘要后可查看工具完成、失败和未确认完成的统计及原始中间过程。

### 4.5 Markdown 与打字机效果

删除整段固定速度平滑输出，改为“稳定内容 + 活跃尾部”的折中策略：

- 已完成的 Markdown 块进入稳定区，不再随每次增量重复参与打字动画。
- 仅对当前纯文本尾部应用打字机效果。
- 尾部追赶速度根据待显示字符数量和帧间隔动态调整。
- 当积压较少时保持逐字感；积压增加时自动加速，避免长时间落后于真实流。
- 代码围栏、表格等结构化 Markdown 尾部直接呈现，降低布局重排和行距抖动。
- 流结束或内容发生非追加式替换时立即同步，避免最终内容仍在慢速追赶。

## 5. 数据持久化与兼容性

- Chat 模式流式过程中继续定时保存 SQLite 快照，应用异常退出后仍可恢复已收到的内容。
- 完成、取消和继续会话路径均保存对应状态及消息元数据。
- `coworkStore` 对新增元数据字段采用可选字段，不要求数据库结构迁移。
- 历史数据没有 `isFinalAnswer` 或 `thinkingDurationMs` 时仍可正常读取；只是不具备新的精确摘要和耗时展示能力。
- 未新增 IPC 通道，现有主进程与 preload 暴露面保持不变。

## 8. 人工回归清单

### 8.1 会话切换

- [ ] 同一项目内切换长历史会话，局部加载态立即出现。
- [ ] 加载完成后直接看到末尾消息，不出现顶部到末尾的可见跳转。
- [ ] 跨项目选择历史会话，不短暂显示新建任务页或旧会话正文。
- [ ] 快速连续点击两个会话，后一次加载态不被前一次请求清除。
- [ ] Work 与 Chat 模式互相切换后，各自会话列表和当前会话状态正确。

### 8.2 流式输出

- [ ] 思考未结束时正文不会提前穿插显示。
- [ ] 最终回答出现前，所有中间回答均保持可见。
- [ ] 最终回答出现后，中间过程自动进入默认折叠的执行摘要。
- [ ] 思考和正文同帧完成时，两条消息均完整，不出现截断。
- [ ] 多段思考分别显示自身耗时，不同步增长。
- [ ] 取消或错误结束时，不产生伪最终回答。
- [ ] 长文本、列表、代码块和表格流式输出时无明显行距抖动。

### 8.3 界面

- [ ] 引擎启动浮层可以收起，紧凑组件可以恢复展开。
- [ ] 引擎错误状态自动展开并可重试。
- [ ] 技能市场单页内容无需内部纵向滚动即可完整展示。
- [ ] 市场搜索和翻页后页码、卡片数量及容器高度正确。
- [ ] 可安装技能显示安装按钮，已安装技能只显示已安装状态。
- [ ] 技能详情中的长描述、来源和 URL 不溢出弹窗。

## 9. 风险与回滚

### 9.1 已知风险

- 不同模型供应方的思考事件顺序可能存在差异；适配器按显式开始、增量和结束事件进行容错，但仍需覆盖实际模型回归。
- Markdown 分段器采用保守提交策略，极端不完整语法可能在流结束前暂留于活跃尾部。
- 技能市场单页数量依赖当前窗口高度和列数；窗口极小时会降至最小页容量。

### 9.2 回滚边界

两个提交按职责拆分，可独立回滚：

1. `feat(ui): refine startup and skill management surfaces`：只影响引擎启动提示和技能管理界面。
2. `fix(cowork): stabilize session switching and streamed responses`：影响会话加载、运行时事件、流式渲染和执行摘要。

如仅发现界面问题，可优先回滚第一个提交；如发现消息时序或会话状态回归，应整体回滚第二个提交，避免只回滚渲染层而保留不匹配的元数据语义。
