# 伙伴任务交代：阶段验收

2026-10-24。在原有持久聊天窗中加入任务交代、工作区选择、近期任务状态、独立停止和同一工作台任务直达。此阶段仍未交付附件与全部产品范围，不能代替整体产品验收。

## 执行与数据边界

- 聊天仍由统一适配器拥有的持久会话承接；显式任务进入原有 Cowork → PiRuntimeAdapter → Workbench Task/Run 链路。没有独立任务执行器、分类模型调用、权限系统或全局模型设置。
- 原 Cowork 启动过程提取为共享的准备与启动入口，保留系统提示、专家、工作区、消息、模型和权限选项。伙伴任务把会话、首条消息、Task、排队 Run 与受理回执放在同一个 SQLite 事务中；提交后才启动适配器，并传入原 Run ID。
- `companion_task_admissions` 只保存身份、请求指纹和原生 ID。`petId + requestId` 唯一，相同请求重试直接返回原回执，内容变化拒绝复用；并发、回执丢失、重开和删除会话均不自动重放外部操作。重启发现未派发的旧排队运行时标记失败，由工作台显式重试。
- 模型从已经同意开启的模型服务自动分配；不写全局默认，不复制密钥。没有模型时不创建任务，草稿、输入用途、工作区和请求 ID 保留。目录可用仍不能证明真实工具或视觉能力。
- 近期任务读取同一 Task 的最新 Run；显式重试在工作台保留 Task ID。状态由原有任务事件推送，只向当前伙伴投影其拥有的任务，不广播其他伙伴的任务正文。
- 打开工作台复用桌宠现有的排队导航、加载确认和失败确认机制。收起窗口不停止任务；独立停止调用原生停止并取消对应运行。普通聊天窗口没有通用应用、模型管理或任意文件 IPC。

## 已验证

- 新增受理与窗口边界、原有桌宠控制与菜单、主窗口接线、分段控件：6 文件、33 项测试通过。包含事务回滚、并发去重、请求指纹、无模型、重开不重放、初始化拒绝、停止、外来身份拒绝、同 Task 重试后的最新状态。
- 适配器回归 15 文件、162 项通过；renderer/shared 344 文件、1867 项通过。完整浏览器预览 38 项通过、1 项原有跳过；另补任务模式各尺寸与热切换专项，任务专项合计 5 项通过。覆盖明暗、448px 窄窗、工作区名称、草稿与请求键、后续编辑保留、任务直达、停止和事件身份隔离。
- 前后端类型、生产构建、常规 Knip、生产 Knip 文件检查、格式、行数、文件大小与包体预算通过；启动图 1.75 MiB、preload 图 0.87 MiB。lint 退出成功，修改文件没有新增警告，不清理无关存量警告。
- 已在未修改 HEAD 复现两项旧菜单测试使用过期「展翅一下」标签；按文件大小规则移到独立菜单测试文件，对齐现有「舒展一下」，保留所有行为断言。没有删除测试或降低门禁。
- 原生验证发现开发构建错误地把 import-only 的运行依赖转为 CJS require；主进程开发脚本和开发监听现与生产采用同一外部依赖边界。真实 Electron 启动已经恢复。
