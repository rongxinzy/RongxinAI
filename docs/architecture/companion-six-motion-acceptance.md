# 六位伙伴连续动作：阶段记录

2026-10-25。本阶段把游栗、团团、绵绵、竹栗、云墨、麦小接入已有连续视频播放器，保留静态回退、任务状态与工作台能力。它完成六位伙伴的连续媒体接线，不代表最终美术、Windows 攀爬或整个智能伙伴产品已经交付。

## 用户可见变化

- 六位伙伴各有 24 段 512×512 / 30fps VP9 alpha 动作，每位 4,410 帧、147 秒。核心包含待机、眨眼、转头、思考、等待、担忧、招呼、行走、拖起与落地；长动作包含 7–10 秒的探看、舒展、庆祝、梳理、舞蹈和瞌睡。
- 游栗侧看时反向摆尾、梳理脸颊、舞蹈时晃头摆尾；团团探看时收爪、双爪搓脸、拍手；绵绵有垂耳摆动、梳理耳侧与轻跳；竹栗动作较慢，梳理时卷尾、舞蹈时小幅侧步；云墨结合探看展翼、翼侧梳理与展翼舞蹈；麦小有抬爪探看、挠耳与较快的交替脚步。共用核心动作不等于性格模型验收。
- 原生菜单的「舒展一下」气泡从仅适合鸟类的「扑棱一下」改为「伸个懒腰。」，英文同步。未新增菜单、设置或模型请求。
- 切换形象释放旧视频，两路视频槽继续复用；失败、待确认、思考高于闲置和点播。免打扰、隐藏与减少动效保留现有优先级。只有 24 条视频、海报和轮廓全部齐全时才启用该角色连续播放。

## 原创素材与作者链路

六张分层源 PNG 使用内置 `image_gen.imagegen`，以各自原姿态图集为身份参照；生成模式为透明背景，实际输出均为 1254×1254。完整初始与局部修订提示词见 [生成记录](../../src/renderer/assets/desktop-pet/rigs/companion-rig-prompts.json)，原图位于同目录的 `<character>-rig-v1.png`。源图保留生成字节，程序没有改原图像素。

离线作者负责部件取景、关节、层次、时间轨迹与视频编码。名义 4×4 网格不能保证生成部件不跨格：曾出现脚越过格边，被固定切片误带进脸部。现在先定位完整透明连通轮廓，再按部件中心归格，并统一四种表情原点。眨眼只有一组眼睛，避免透明表情叠加产生重影；长时间放松动作有完整闭眼停留。抬脚轨迹触地处斜率归零，循环与睡醒连接有行为测试。

保留 MIT dsh-pet 的双缓冲机制与归属，不移植其动物素材。产品仍使用原生 HTMLVideoElement，无新增产品依赖；宿主 FFmpeg 只做离线编码、核验，编码和解码线程均有界为 2。幼龙舞蹈初版略超既有 2 MiB，完整重建采用 CRF 28，其余为 25；没有减少帧数、分辨率或放宽门禁。

七包共 168 段、30,870 帧。单角色仍受 40 MiB、单文件仍受 2 MiB 限制；实际容量、最大文件、原图哈希和逐包核验记录见 [媒体审计](../companion-six-motion-2026-10-25/media-audit.json)。URL 清单被打包不等于全部视频预加载；只为当前状态使用两路槽位。完整重建命令见 [素材说明](../../src/renderer/assets/desktop-pet/motion/README.md)。

## 实际检查

- 已观看真实视频的梳理、舞蹈、行走、思考、瞌睡和醒来，比较不同时间的关节位置与脚步。六角色同屏仅是临时作者审阅页，不进入产品，也不作为产品并行六只的性能承诺。实际截图：[浅底](../companion-six-motion-2026-10-25/dance-light.png)、[深底](../companion-six-motion-2026-10-25/dance-dark.png)。临时页未报告控制台错误或警告。截图只证明抽样画面，不代替完整时间上的动画判断。
- 七包完整来源/编排哈希、视频/海报/轮廓哈希、libvpx-vp9 RGBA 全帧解码已通过。新增独立 PNG 验证非空、二值 alpha、画布安全边距与记录边界；合成夹具覆盖跨格部件和眨眼重影问题。格式化后的最终清单也已完成对应字节核验，总计 181,968,521 字节，结果见媒体审计。一次核验遇到宿主 FFmpeg 启动超时；约束解码线程并结束其他重任务后串行完整通过，保持原有 15 秒上限及全部断言。
- 桌宠/主进程菜单/媒体作者相关 18 文件、73 项测试通过；renderer/shared/作者回归 352 文件、1,893 项通过。新测试验证全部七种包、完整曲目、换形象清理、未知形象回退，以及六种招牌动作的不同编排。
- 真实 Electron 44.9.3 / macOS arm64 / DPR 2，使用独立临时目录、真实网关与本机 SSE 夹具：同一 Task/Run 打开工作台，一次业务执行加两次既有记忆维护；任务中开启免打扰仍完成，恢复播放完成动作。随后逐个切换六形象，经真实原生菜单播放探看和舒展，每次都只有两个槽位、一个活动来源，来源属于当前角色，免打扰时两路暂停并移除来源。结构化 [结果](../companion-six-motion-2026-10-25/native.json) 与六份 `native-<character>.png` 保留。没有真实模型质量、工具审批或 Windows 证据。
- lint、常规/生产 Knip、生产构建、主进程类型、格式、行数、已暂存大文件与文件 token 检查通过；当前改动无新增警告，仓库其他文件的既有警告与 Vite 提示没有宣称清零。启动图约 1.76 MiB、preload 图约 0.87 MiB，原预算通过。
- 最终完整 `bun run web:preview:check`：87 项通过、1 项既有显式跳过，6.9 分钟。覆盖七包全部 168 段实际中间帧、七形象 × 六任务状态 × 明暗、真实播放进度与命中轮廓、任务优先级、隐藏/减少动效，以及伙伴首页、快捷窗、附件、设置、工作台和流式回放。warn-only 无障碍抽检仍报告既有 `aria-required-children`，不作为全产品无障碍通过。
- 首轮曾发生制作/构建期间热重载和 HTTP/HMR 端口不一致，随后批量导航矩阵还出现 HMR 重连及开发客户端 Blob Worker 被 CSP 拒绝。修正验证环境，并把状态矩阵改为原生窗口实际使用的就地状态更新；全部 84 组像素/边界检查保留，未放宽产品 CSP 或原超时。另一轮有一项流式用例在创建测试页面阶段超时，最终串行完整复跑通过；未修改该用例或断言，不据此推断已经确定宿主超时根因。

原生可复跑：准备现有真实网关资源、开发主进程构建及预览后运行：

```bash
PREVIEW_PORT=5194 COMPANION_VERIFY_ALL_MEDIA=1 bun scripts/companion/verify-task-electron.mjs
```

端口随实际预览填写，HTTP 与 `VITE_DEV_PORT` 必须一致。验证不会修改真实用户配置，也不会启动第二套任务内核。

## 保留的缺口

小远羽毛边缘和尖喙修订、所有动作的最终美术验收仍待完成。当前是分层关节的连续全身动画，尚无全角度转身或透视网格变形；不能称为最终高表现力美术已经达标。七包约 173.5 MiB 的资源占用需要继续评估，两个解码槽不证明小时级无泄漏。
