# 气泡任务附件：拖放与粘贴

2026-10-26，基于 `215bcb35`。本阶段完成输入区任务文件的拖入与粘贴，保留原生文件选择、独立草稿、工作区、既有 Task/Run、附件授权和失败处理。记忆依赖冻结，没有修改模型配置、候选运行时或欢迎动画。

## 行为与边界

- 复用工作台 `usePromptFileDrop`、共享 PromptInput 与附件行。文件事件在输入区捕获阶段只消费一次；普通文字粘贴保持浏览器默认行为。
- 原生选择仍为原文件引用。拖放/粘贴的 File 在渲染器异步读取，每次仅一个不超过 25 MiB 的二进制 IPC；主进程异步写入既有应用临时附件目录，再产生当前伙伴的授权 ID。没有通用路径参数、base64 解码、图像解析、扫盘或哈希；UUID 文件名与独占创建阻止覆盖，授权失败删除本次临时文件。
- 草稿只保存 `id/name/bytes`。写入后的字节和路径由原有授权目录持有，其他伙伴、错误 frame 和过期身份不能读取或暂存。系统清理临时文件后仍按既有「附件已不可用」流程保留草稿并让用户重新选择，不承诺附件永久保存。
- 仍为最多十个附件；批次超数量或任一超大小时，在读文件前拒绝整批。暂存逐项进行，若后续读取/存储失败，之前已成功的附件和当前文字都保留；锁防止原生选择与连续拖放重叠。迟到结果不越过身份切换。
- 聊天收到附件仅提示「处理文件请切换到交代任务」，不会自动切换、消耗一次聊天或声称模型能看图。任务图片和真实视觉模型的能力验证属于后续范围。
- 实际截图发现空任务区被压成细条、附件第二行底部裁切。空任务列表不再重复输入提示；真实消息/任务区保留最小可读空间，并复用共享滚动焦点 recipe；两行附件完整展示。没有新增色系、外观开关、说明卡或样式例外。

## 后续阶段：气泡聊天图片（2026-10-26）

聊天沿用同一个附件入口、输入区、文件暂存和授权引用，接受图片选择、拖入与粘贴，也支持不填文字直接发送图片。其他文件仍指向「交代任务」，不自动切换。没有把聊天放回主界面，没有新增模型设置、角色形象、欢迎动画、主题或记忆依赖改动。

图片请求从现有已授权模型目录自动筛选视觉输入，仍优先符合要求的默认模型；不会为了图片改写全局默认、启动未获同意的服务或发送给新的目的地。当前原生上下文及尚未放入会话的 inbox 含图片时，文字跟进和重开后的恢复也继续要求视觉模型；无可用项时保留草稿/请求，不悄悄丢掉图片。目录声明只用于选择，不能证明真实视觉理解质量。

主进程复用当前伙伴的路径、过期和所有权检查；图片读取、格式魔数、像素限制、归一化及 base64 均在已有最多两个 Worker 的池里处理，带队列限制、取消和超时。复用 Pi 的 Photon，新增精确锁定的 [image-size 2.0.4](https://github.com/image-size/image-size) 做解码前的头部检查；它被编入 Worker，作为构建依赖，不扩大安装包运行时依赖允许范围。没有新建执行框架、使用 Electron API 处理图片或在主线程回退解码。

输入仍受原来的每文件 25 MiB、十文件门限约束；解码前另限 3,200 万像素和单边 16,384，模型图片归一到最多 2000×2000、单张 base64 1 MiB、每批合计 4 MiB。Photon 的 WASM 峰值内存不会主动缩小，因此每批图片完成即回收其 Worker 槽，不在闲置状态保留照片大小的堆；后续普通 artifact 任务能正常恢复。WASM 与旧 photon-node ABI 不混用，开发及生产复制为独立的 `companion-photon.wasm`。

只有原生持久会话保存模型图片输入；前端历史与草稿仍只有文字、名称和授权引用，不返回路径/base64。图片受理和请求去重同一条提交线；回执已存在时不再读取原文件，文字或附件的新编辑不会被旧回执清空。坏图、过大图片、失效引用、无视觉模型分别给简短提示，不把内部路径或解码错误直接显示出来。
