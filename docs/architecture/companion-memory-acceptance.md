# 伙伴私有记忆阶段记录

本阶段复用现有 Engram、SQLite 投影、outbox 和个人记忆确认流程。伙伴对话继续通过统一适配器持有的 Pi Durable 执行，不安装第二套记忆或模型执行框架。完整产品范围仍以 [总清单](intelligent-companion.md) 为准。

## 行为与边界

- UUID `petId` 决定私有命名空间 `companion://zhiyuan-agent/<petId>`。换装保持身份，切换伙伴改变召回范围；普通工作台记忆列表和手动编辑不暴露私有条目。
- Engram 的传输只有项目、个人、会话三种范围。适配器明确将伙伴范围映射为项目传输，保持独立命名空间；本地投影继续记录 `companion`。不能依赖后端对未知 scope 的隐式回退。
- 用户主动添加、编辑、删除。标题 120 字符、正文 3,000 字符上限，复用已有隐私脱敏与敏感凭据拒绝。编辑通过替代关系使旧事实退出召回。
- 保存请求使用稳定请求 ID 与内容摘要去重。待同步写入复用现有 outbox；撤回未同步请求会删除候选与排队项，另留请求哈希和撤回时间，重试或新数据库连接不能重新创建该条目。已同步记录沿用软删除，退出召回；伙伴列表接口只返回有效和待同步记录，不返回已删除或被替代内容。
- 在途写入完成后再次核对候选和关系。若用户已撤回候选或删除共享来源，远端观察不进入可召回投影，清理复用持久 outbox；清理暂不可用时可重试。
- 私有记忆共享前显示原文并确认。确认后经既有个人记忆候选/确认路径创建独立副本，保留来源关系。离线共享重试不重复入队；已经确认的个人副本不会随私有原件删除而消失，之后可在工作台记忆设置管理。
- 原生提示节按当前伙伴和本轮输入检索相关事实，私有/已确认个人预算分别为 900/250 token。无相关事实不加入提示；检索失败降级为空，不阻塞聊天。Pi 原生节更新负责去重与移除旧内容，不加模型分类调用。
- 本文记录伙伴聊天阶段；后续已接入任务召回、写入、摘要与历史隔离，见[任务阶段记录](companion-task-memory-acceptance.md)。聊天自然语言记忆管理、真实模型记忆使用质量及完整产品验收仍需继续。

## 界面与设计依据

依据 DESIGN.md 的密度、圆角、表面、列表、Dialog、Button、i18n 与伙伴章节。主窗和快捷窗共用顶栏入口，复用 Field、Input、Textarea、Separator、Button、Dialog 与 DestructiveConfirmDialog。工作台原有编辑器按文件大小规则机械提取为独立组件，保留原有功能，并显式排除伙伴范围。

实际对照发现共享弹窗仍有背景模糊，深色主题缺少 v4 圆角映射，独立 Input/Textarea 还沿用低对比度边界；本阶段在共享 recipe/主题处修正，未添加局部覆盖、主题或基线豁免。输入复用现有中性文字 token 作描边、2px 不透明焦点环及 120ms 过渡；弹窗内容 24px、字段间距 16px、桌面最大宽度 512px；448px 窗口按共享安全边距提供 416px 可用宽度，不缩小文字或控件。弹窗过渡 200ms，减少动效沿用主题引擎。

## 私有任务候选审阅（2026-10-25）

任务提炼的候选现在显示「待确认」，用户点「查看」后在原弹窗审阅原文，确认「记住」才写入所属伙伴记忆。取消不确认，删除沿用既有危险操作确认；已经批准但离线的记录显示「待同步」。确认不共享，个人共享仍是独立确认操作。标题、正文与种类作为审阅快照由主进程核对；内容变化、另一伙伴或撤回后的请求不能被确认。相同确认丢失回执后重试返回原记录，离线重试不重复投递。

两处窗口都通过新增的严格 IPC 契约调用同一服务，持久队列与在途撤回仍复用既有 outbox。另一窗口修改后刷新已打开的列表；当前写入收到回执后再刷新，推送不能提前抹掉写入错误。没有增加依赖、主题、模型调用或用户模型设置。共享只读审阅内容抽为独立组件，正文滚动和底部按钮继续分离。

真实双窗口验收曾触发 IPC 队列上限。排查发现终态回执被重复广播，bootstrap 创建的等价回执对象又使轮询不断重启。修复为每条终态回执只通知一次、按回执字段保持轮询生命周期，并将突发失效通知合并为一次在途读取与一次后续读取；隐藏时丢弃排队刷新。原队列上限仍为 8，未提高容量或放宽检查。
