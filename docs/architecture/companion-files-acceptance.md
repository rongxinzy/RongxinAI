# 伙伴任务附件阶段验收

日期：2026-10-25。分支 `codex/intelligent-companions`。本阶段补齐主窗口与快捷窗的任务文件选择和执行，整体产品仍按 [完整清单](intelligent-companion.md) 推进。

## 行为与执行边界

在「交代任务」的输入栏左侧添加附件按钮，原生多选文件；文件名复用工作台 CoworkInlineAttachments / ai-elements，按钮复用 PromptInputButton，没有新配色、卡片或外观设置。文件最多两行后滚动；输入区在最小客户区可滚动，文字不缩小。选取取消不改变草稿，选取期间允许编辑文字；无模型、受理失败和附件不可用均保留内容。旧回执不会清空新文字或移除后的附件版本。

原生桥接只接收 petId，不接受 renderer 提供的路径。校验注册主窗/快捷窗的主 frame、当前伙伴与对话框互斥；对话框结束后重新校验身份并在串行队列中登记。只返回 UUID、文件名和字节数，草稿中没有路径、base64 或文件内容。

引用目录位于现有 SQLite 的 `companion_attachments` 表，按伙伴隔离，有效期 30 天；过期仅清除引用，不删除原文件。选取与受理前通过异步 realpath/stat 确认文件仍有效，拒绝目录、失效引用、跨伙伴引用、重定向和超限。最多 10 个文件，每个 25 MiB。没有主进程整文件读取、哈希或内容解析。

受理继续使用 CompanionTasks → prepareCoworkSession → PiRuntimeAdapter。附件走既有 fileAttachments 元数据、权限和文件工具；文件引用进入该任务的运行上下文，用户消息原文不变。图片保留 `isImage`，以既有文件引用方式交给工具；本阶段没有将图片 base64 直接送入聊天。未新增执行器、解析库或模型设置。

同请求的原回执先于附件复验返回。因此受理后原文件被删除，或回复丢失后重试，不会重新启动任务。改变附件集合却复用原请求 ID 会被拒绝。附件已不可用时提示用户移除并重新选择，状态刷新不再覆盖该提示；文件错误不显示无法解决问题的「刷新状态」按钮。

实际补测发现共享文件详情在 448px 窗口中被长文件名撑到约 1004px。已在共享 CoworkInlineAttachments 约束 320px 内容列、文件名/类型换行与图片最大宽度，修复同时适用于工作台。移除按钮增加文件名辅助描述；不改动主题外观、浮层引擎或碰撞边界。

原组件单测原先锁定浮层 `nowrap / w-max`，与这次已复现的窗口溢出修复冲突。更新后仍保留行内文件名头尾与完整详情文字的断言；实际宽度、完整名称不截断及明暗窗口边界由新增浏览器断言检查，没有删掉文件名或放宽窗口边界。

系统主题补测还复现快捷窗缺失媒体偏好监听：收到 `system` 配置后，系统从浅色变暗仍保持浅色。快捷窗现在先初始化既有 ThemeService，再应用主进程上下文；监听只注册一次，显式浅色/深色设置仍优先。原生夹具用受控媒体偏好切换验证两窗同步，不宣称已人工操作 macOS 系统设置。

## 真实原生链路

隔离 userData / 工作区，Electron 与真实 Magpie 网关连接本机 SSE 夹具，没有使用真实账号或模型。只有系统文件选择器的返回值被替换为合成文件；原生文件选择器本身的人工操作体验未验收。其余主 frame IPC、引用目录、Task/Run、文件权限、read 工具和工作台均为实际实现。

1. 文件选择经过真实桥接，快捷窗草稿只保存不透明元数据。
2. 夹具先确认模型上下文确实包含所选文件引用，再请求标准 read 工具。第二次请求的实际工具结果包含该文件的唯一随机标记。
3. 同一个业务任务完成，工作台显示原始用户文字、附件行与 read 轨迹；没有 JSON/路径清单占用用户消息。
4. 文件移除后再次提交同请求，返回原回执，没有执行第二个任务。
5. 同次验收保留主/快捷窗共享聊天、身份与换装隔离、免打扰时执行继续、隐藏媒体释放与完成动作。

原生进程退出后，另一个 Node 进程以只读方式打开磁盘上的 `zhiyuan.sqlite`，确认该伙伴的附件引用仍有 1 条，受理表的 Task/Run 与原回执一致；结果记录在报告的 `postClosePersistence`。这证明引用与回执已落盘，完整应用重启后的草稿、权限和 UI 恢复仍需端到端验收。

记录为 1 个 Task/Run、2 次任务模型请求（工具调用前后各一次）、1 次伙伴聊天、2 次既有记忆维护，共 5 次模型请求。该证据不代表真实模型主动选工具的质量、真实文档解析效果、模型用量计费或 Windows 行为。

复现：准备已验证的 Magpie，先 `bun run build:electron:dev`，启动浏览器预览，再串行执行：

```bash
PREVIEW_PORT=5194 COMPANION_VERIFY_HOME=1 COMPANION_VERIFY_FILES=1 bun scripts/companion/verify-task-electron.mjs
```

不要和会写入 dist-electron 的 build/Knip 并行。常规验收不启用这项手动原生夹具。截图与报告在 [本阶段证据目录](../companion-files-2026-10-25/native-report.json)。
