# 移除外部 NIM 频道插件说明

> 日期：2026-05-13
> 分支：fix/deleteNIMapp
> 范围：OpenClaw 预装频道插件与运行时配置同步

## 背景

项目此前会在 OpenClaw 运行时预装一个外部 NIM 频道插件，并在配置同步阶段根据本地 IM 设置自动写入对应的插件启用状态、频道账号配置、密钥环境变量和智能体绑定关系。

该频道已经不再作为默认随应用分发的能力，因此需要从预装插件列表中移除，并确保旧配置不会继续让运行时尝试加载已经不存在的频道插件。

## 目标

1. 不再随应用构建和运行时准备流程安装外部 NIM 频道插件。
2. 配置同步时清理历史遗留的 NIM 插件入口，避免 OpenClaw 启动时出现无效插件加载。
3. 未显式提供兼容插件时，不再写入 NIM 频道配置、密钥环境变量和频道绑定配置。
4. 保持现有本地配置结构和 UI 类型暂不破坏，为后续完整移除或迁移预留空间。

## 变更范围

### 插件安装入口

`package.json` 中移除了外部 NIM 频道插件声明。后续执行 OpenClaw 运行时构建或插件准备脚本时，不会再下载、缓存或复制该插件到运行时扩展目录。

### OpenClaw 配置同步

`OpenClawConfigSync` 增加了对已移除 NIM 插件入口的清理：

- 清理旧的包名入口。
- 清理旧的 manifest 入口。
- 避免把已移除插件重新写回 `plugins.entries`。

同时，NIM 频道配置写入变为显式插件存在时才启用：

- 如果运行环境没有声明兼容 NIM 频道插件，不写入 `channels.nim`。
- 不写入 NIM 专用密钥环境变量。
- 不写入 NIM 频道级智能体绑定。
- 如果某个部署未来主动重新声明兼容插件，配置同步逻辑仍可按原结构生成对应频道配置。

### 测试调整

相关测试已更新：

- 插件安装脚本测试不再使用被移除的真实频道插件作为示例。
- 运行时配置同步测试覆盖旧 NIM 插件入口的清理行为。
- 测试断言确认旧插件入口不会保留，也不会在缺少兼容插件时写入 NIM 频道配置。

## 保留内容

本次改动只移除默认预装的外部频道插件，不做完整平台级删除。以下内容暂时保留：

- 本地 IM 配置类型。
- 设置页中的 NIM 配置结构。
- 历史数据读取与迁移逻辑。
- 本地 SDK 相关代码。
- 二维码配置辅助入口。

保留这些内容可以避免一次性删除造成已有本地数据、类型依赖或设置页状态出现大范围破坏。后续如果确认要彻底移除 NIM 平台能力，应另开任务逐步清理 UI、IPC、类型、持久化和测试。

## 行为变化

### 新安装或重新构建运行时

应用不会再默认安装外部 NIM 频道插件。OpenClaw 配置中不会自动出现该频道插件入口。

### 已有用户配置

如果旧配置中残留相关插件入口，下一次配置同步会将其移除，避免运行时继续尝试加载不存在的插件。

### 显式自带兼容插件的部署

如果某个部署主动在预装插件清单中重新声明兼容 NIM 频道插件，配置同步仍会识别该插件并写入对应频道配置。这保证了默认移除和定制部署之间的兼容边界清晰。

## 风险与缓解

### 风险：旧配置残留导致启动警告

缓解：配置同步会清理旧插件入口，避免重复写入无效插件项。

### 风险：现有 UI 仍可编辑 NIM 配置

缓解：本次只移除默认频道插件，UI 暂不作为运行时能力承诺。后续若要彻底隐藏入口，需要单独处理平台注册、设置页、类型、IPC 和文案。

### 风险：定制部署仍依赖该频道

缓解：同步逻辑保留了显式声明兼容插件时的配置生成能力。默认发行版移除插件，不阻断有明确需求的定制构建。
