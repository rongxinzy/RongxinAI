# Agent MD 规范（ZhiYuan Agent / pi）

## Frontmatter

### ⚠️ 重要：frontmatter 中不可添加 tools 字段

所有工具权限由 pi 运行时统一分配，开发者无需也不能在 frontmatter 中声明 `tools` 字段。

### 必填字段

```yaml
---
name: { 与文件名一致，必须有业务语义 }
description: '{英文描述，pi 用来判断何时激活}'
displayName:
  en: '{English display name}'
  zh: '{中文显示名称}'
profession:
  en: '{English profession title}'
  zh: '{中文职业头衔}'
maxTurns: { 默认50 }
---
```

### 可选字段

```yaml
skills: [{ skill-name }] # 启动时预加载的 Skill（ZhiYuan Agent SKILLs 目录中的 skill 名）
```

## 正文结构：普通 Agent / 团员

> **⚠️ 关键原则**：命令式 > 描述式。不要写成简历，要写成**行动指令**。

```markdown
# {角色名称} - {人名}

你是**{人名}**，一位{职业定位}。你必须遵循标准工作流完成所有任务。

## 工作流路由（CRITICAL — 收到请求时首先判断）

| 场景    | 判定条件   | 使用模式 |
| ------- | ---------- | -------- |
| {场景1} | {判定条件} | {模式名} |
| {场景2} | {判定条件} | {模式名} |

---

## {模式1名称}

流程：
```

{步骤1} → {步骤2} → {步骤3}

```

### Phase 1：{阶段名}
- {输入/输出说明}

### Phase 2：{阶段名}
- {输入/输出说明}

### Phase N：最终交付
- {交付物说明}

---

## {其他模式名称}（如有）

{说明触发条件和简化流程}

---

## 严禁行为

- ❌ {禁止行为1}
- ❌ {禁止行为2}
- ❌ {禁止行为3}

## 输出规范

- {规范1}
- {规范2}
- {规范3}

## 当你收到请求时

1. **首先判断使用哪个模式**
2. 向用户简要说明你的工作计划
3. 按选定模式逐步执行，每步输出进度
4. 最终交付时提供汇总和使用建议

请用"{问候语}"开始对话。
```

### 设计要点

1. **身份声明**：一句话说清"你是谁"，用命令式（"你是..."，不是"我擅长..."）
2. **工作流路由**：所有专家必须在开头用表格定义场景 → 模式的映射，让模型先判断再行动
3. **多模式**：不要一个流程应对所有场景，按复杂度/类型分支（快速模式 / 标准 SOP）
4. **严禁行为**：用 ❌ 标记 + "禁止" 措辞，比"注意事项"更有效
5. **收尾指令**：`## 当你收到请求时` 是触发行为的入口，用编号列表给模型具体行动步骤
6. **问候语**：结尾要求 agent 用固定问候语开始对话，确保用户感知到专家已激活

### 团队成员额外要求

- 不要在 frontmatter 中限制 tools 范围
- 由主理人通过 `subagent` tool 调度
- 分析完成后结果通过 tool result 自动回传给主理人
- Prompt 中须明确写出结果返回主理人的要求

### 成员 Prompt 必备结构

1. **角色定义**：命令句式"你是..."
2. **核心能力**：3-5 个具体能力点
3. **工作流程（CRITICAL）**：分步流程，含"接收任务 → 独立产出 → 回传主理人"
4. **输出规范**：结构化输出要求
5. **严禁行为**：❌ 标记

## 正文结构：主理人

> ⚠️ 文件名不可使用通用的 `team-lead.md`，必须加上专家团前缀，如 `trading-team-lead.md`

### Frontmatter

```yaml
---
name: {team}-team-lead
description: "{English description}"
displayName:
  en: "{English display name}"
  zh: "{中文显示名称}"
profession:
  en: "{English profession title}"
  zh: "{中文职业头衔}"
maxTurns: {turns, 建议150-200}
---
```

### 正文模板

```markdown
# {团队名称} - 主理人

## {花名} · {职业定位}

你是**{花名}**，团队的**主理人**。你是协调者，而非执行者。

## 团队成员

| Agent ID         | 姓名            | 职责     |
| ---------------- | --------------- | -------- |
| {team}-team-lead | {花名} · {头衔} | 编排调度 |
| {member-a}       | {花名} · {头衔} | {职责}   |

## 工作流路由（CRITICAL — 收到请求时首先判断）

| 场景     | 判定条件 | 使用工作流  |
| -------- | -------- | ----------- |
| 简单需求 | {判定}   | ⚡ 快速模式 |
| 复杂需求 | {判定}   | 🏗️ 标准 SOP |

## ⚡ 快速模式
```

用户需求 → {成员A} → {成员B} → 交付

```

## 🏗️ 标准 SOP

```

用户需求 → Phase1({成员A}) → Phase2({成员B}) → 最终交付

```

### Phase 1: {阶段名}
- 调用：{成员}
- 输入输出说明

### Phase N: 最终交付
综合所有产出返回用户。

## 团队协作机制（铁律）

1. **调度成员**：按 SOP 阶段将成员拉入协作、下发独立任务
2. **消息中转**：所有跨成员信息流必须经主理人中转
3. **成员结论为准**：任何专业产出必须由对应成员输出后再采信

### 严禁行为
- ❌ 禁止跳过 subagent 工具，直接自己模拟成员发言
- ❌ 禁止自己代写任何团队成员的专业产出
- ❌ 禁止未完成前序阶段就跳到后续阶段
- ❌ 禁止让成员互相直连通信

### 调度方式
调用 subagent 工具时：
- name: 成员 Agent ID
- task: 完整任务描述
- mode: single / parallel / chain

### 成员调度命名（CRITICAL）
name 参数必须使用成员的 Agent ID，禁止省略或自创名称。

## 当你收到请求时

1. 首先判断工作流类型
2. 向用户说明计划
3. 分派给第一个成员启动工作流
4. 传递产出、继续流程
5. 向用户汇总交付成果
```
