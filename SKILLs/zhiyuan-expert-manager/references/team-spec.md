# Team 型专用规范（RongxinAI / pi）

## 成员命名规范

Team 型专家团中，每个成员有三个外露字段：`name`（名字）、`profession`（职业头衔）、`nickname`（昵称，可选）。三者不应重复。

### name：谐音花名风格

| 规则 | 说明 |
|------|------|
| 建议三个字 | 姓+名，建议三个字，两个字也可 |
| 先是正常人名 | 姓+名结构，不解释也能当名字用 |
| 暗含职能巧思 | 谐音、拆字、典故均可，但不刻意 |
| 不与 profession 重复 | name 是"谁"，profession 是"做什么" |
| 中英文都自然 | 中文用花名，英文用拼音姓氏 |

### 主理人 profession 规范

主理人的 `profession` 不能用通用 title（团长、主理人、Team Lead），应体现该团队的调度风格和业务定位。

## 协作铁律

1. **调度成员**：按 SOP 阶段将成员拉入协作、下发独立任务；成员作为独立协作方输出专业产出，不得由主理人代写
2. **消息中转**：成员产出回传给主理人，由主理人汇总、转交下一阶段；所有跨成员信息流必须经主理人中转，不得互相直连
3. **成员结论为准**：任何专业产出必须由对应成员输出后再采信，主理人只做编排与汇编

### 5 条红线

- ❌ 禁止跳过 `subagent` 工具，直接自己模拟成员发言或并行写出多角色内容
- ❌ 禁止自己代写任何团队成员的专业产出
- ❌ 禁止未完成前序阶段就跳到后续阶段
- ❌ 禁止让成员互相直连通信，所有跨成员信息流必须经主理人中转
- ❌ 禁止 spawn 主理人自己（编排、汇总、决策由主理人亲自完成）

### 协作规则

1. 所有成员调度必须经过"调度成员 → 成员回传"正式流程
2. 每阶段结束后，将完整产出原文传递给下一阶段
3. 调度成员时，在 `subagent` 工具的 `name` 参数中传入该成员的 **Agent ID**（agents/ 下的 MD 文件名，不含 .md）
4. 裁决型角色必须给出明确结论，不得回避决策
5. 每完成一个阶段向用户简要通报进度

## SOP 工作流编排

### 并行 vs 串行

- **并行 Phase**：同一条消息中 spawn 多个成员（使用 `subagent` parallel 模式），适用于成员间无数据依赖
- **串行 Phase**：等前一 Phase 全部回传后，将结论传入下一 Phase 的成员 prompt（使用 `subagent` chain 模式）

### 示例 SOP

```
Phase 1（并行）：
  stock-researcher → 基本面+财务
  valuation-pricer → 估值判断
  money-tracker   → 资金态度

Phase 2（串行，Phase 1 结论传入）：
  risk-doctor → 综合风险诊断

主理人汇编 → 输出
```

### 预设 Workflow 设计原则

每个 Workflow 写明：
- **触发条件**：什么类型的问法匹配此 Workflow
- **Phase 编排**：分 Phase 的串并行调度
- **输入输出依赖**：每个 Phase 的输入来自哪里、输出传给谁

Workflow 数量根据用户实际高频场景设计，不是越多越好。

## 与 WorkBuddy 的差异

| WorkBuddy | RongxinAI / pi |
|-----------|----------------|
| `TeamCreate` | 无需显式创建团队，主理人直接调用 `subagent` |
| `Agent spawn` | `subagent` tool |
| `SendMessage` | tool result 自动回传 |
| 成员常驻上下文 | 每次 `subagent` 调用携带完整任务描述 |

## 主理人 Prompt 必备章节

1. **团队定位**：一句话说明团队解决什么问题
2. **成员能力清单**：Agent ID、擅长领域、典型问法
3. **预设 Workflow**：触发条件 + Phase 编排
4. **单 agent 直调路由表**：什么类型问题直接调哪个成员
5. **subagent 调用规范**：name / task / mode 参数说明
6. **协作铁律**
