# 内容简报与形式路由

## 目标

动笔前先把"写给谁、为什么写、写成什么样"钉死，然后路由到正确的写作技能。**先简报，后动笔。**

## 工作流

### Step 1：信息收集

向用户确认（缺失时给出合理默认并标注假设）：

- 受众：谁在读？他们的知识水平与关注点
- 目标：读完要做什么/感受什么（转化、认知、行动）
- 渠道与形式：文章 / 社媒短文案 / 广告 / 新闻稿 / 邮件 / 视频脚本
- 语气与调性：专业 / 轻松 / 官方 / 情感向
- 长度与格式要求

### Step 2：输出内容简报

```
**受众**: [谁在读 + 关注点]
**目标**: [读完后的行为/感受]
**形式**: [文章/社媒/广告/...]
**语气**: [调性描述]
**核心信息**: [一句话主信息]
**关键点**: [2-3 个必须覆盖的点]
**禁忌**: [不能说的、品牌禁语、合规红线]
```

### Step 3：形式路由

| 内容形式 | 路由到 |
| -------- | ------ |
| 广告文案 / 品牌文案 | `ad-copywriter` / `ad-creative` |
| 营销活动文案 | `marketing-writer` / `campaign-planner` |
| 社媒爆款 / 病毒传播 | `viral-writer` |
| 电商详情 / 商品文案 | `ecom-copy-assistant` |
| 客服回复 / 挽留话术 | `customer-reply-craft` / `churn-prevention` |
| 深度文章 / 研究型内容 | `content-research-writer` / `deep-research` |
| 通用撰稿 / 改写润色 | `copywriting` / `copy-editor` / `humanizer-zh` |
| 会议纪要 / 流程文档 | `meeting-recap` / `process-doc` |
| 事实性内容查证 | `web-search` |

### Step 4：动笔与自检

- 按路由技能的工作流撰写
- 自检：核心信息是否在开头 30% 内出现；语气是否与简报一致；禁忌是否为零
- 交付文件用 `declare_artifact` 声明

## 严禁行为

- ❌ 禁止跳过简报直接动笔
- ❌ 禁止编造数据、引语、客户案例与来源
- ❌ 禁止输出与受众/目标脱节的"通用好文"
