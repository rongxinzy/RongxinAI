需求规格 · 可逐条验收

FR-01
基于有权限的知识源生成建议

答案必须携带段落级引用；无可靠来源时明确提示“未找到依据”。

P0 / MUST
FR-02
客服可以编辑后再发送

生成内容只进入草稿区；发送动作由人工明确触发并写入审计记录。

P0 / MUST
FR-03
支持反馈建议质量

记录采纳、编辑、拒绝原因；不把客户隐私或完整工单正文写入训练集。

P1 / SHOULD
FR-04
知识过期时提示维护人

引用失效、权限撤销或文档超过有效期时，不继续展示旧建议。

P1 / SHOULD
NFR-01
权限与审计

建议检索沿用源系统访问权限；每次生成记录模型版本、引用 ID 与操作者。

P0 / MUST

交互流程与风险边界

01 · 读取取工单摘要与用户权限
02 · 检索仅搜可访问且有效文档
03 · 起草生成带段落引用的建议
04 · 审阅人工编辑、采纳或拒绝
GIVEN
当引用知识均有权限且处于有效期

系统返回建议文本、来源标题、原文片段、更新时间。

ACCEPT
WHEN
当检索结果不足或互相冲突

系统展示冲突来源并停止给出操作性结论，不补造答案。

SAFE
THEN
当操作者点击采纳

只回填草稿；任何外发、退款或账户更改仍需独立授权流程。

HUMAN
待决策 / 安全敏感字段脱敏发生在检索前还是模型调用前？需安全负责人确认。
待决策 / 运营知识文档的过期 SLA 与责任人如何定义？进入试点前明确。
