## 1. 产品概览

RongxinAI 是一款基于 Electron 的桌面端 AI 工作台。它把对话、任务编排、本地模型推理、技能扩展、MCP 工具接入、IM 机器人和定时任务放在同一个界面中，适合个人效率场景和团队自动化场景。

你可以把它理解为三层：

- `对话工作区` 负责会话、消息、工具调用和执行状态
- `OpenClaw` 负责执行引擎
- `Ollama` 负责本地模型服务和本地推理

## 2. 第一次使用

### 2.1 启动后先做什么

首次打开应用后，建议按下面顺序配置：

1. 进入 `设置`
2. 配置一个可用的模型提供商
3. 如果需要本地推理，安装并启动 `Ollama`
4. 如果需要自动化执行，确认执行引擎配置
5. 如果要接入工具或消息渠道，再配置 `MCP`、`IM` 或定时任务

### 2.2 模型提供商

当前支持多种模型提供商，包含 DeepSeek、Moonshot、Qwen、Zhipu、MiniMax、Volcengine、Qianfan、StepFun、Xiaomi、Ollama，以及自定义提供商。

配置时通常需要：

- API Key
- Base URL
- 模型名称
- 可选的 API 格式或能力开关

## 4. 对话工作区

对话工作区是默认的任务入口，适合让 AI 处理编码、文档、分析和工具调用。

### 4.1 基本用法

1. 点击 `新建任务`
2. 输入任务描述
3. 选择需要的模型或保留默认模型
4. 发送消息，等待 AI 回复

### 4.2 你可以做什么

- 连续追问
- 让 AI 读文件、改代码、写说明
- 在任务过程中切换模型
- 上传图片或文档
- 通过权限弹窗控制工具执行

### 4.3 会话管理

会话会自动保存到本地数据库。你可以进行：

- 重命名
- 置顶
- 删除
- 搜索历史会话
- 继续上一轮任务

### 4.4 运行模式

对话工作区的执行由 `OpenClaw` 驱动。常见场景下你不需要直接接触引擎层，但当需要排查权限、工具执行或消息同步问题时，可以在设置里查看相关配置。

## 5. 本地推理

本地推理页用于管理 `Ollama` 和本地模型，分成三个标签页：

- 推理调试
- 模型管理
- 模型市场

### 5.1 推理调试

这个页面用于直接测试模型效果。常见用途：

- 验证模型是否能正常回复
- 调整采样参数
- 对比不同模型的输出风格
- 检查思考过程和生成速度

#### 常用参数

| 参数 | 说明 |
|---|---|
| `temperature` | 控制随机性，越高越发散 |
| `top_p` | 控制概率截断范围 |
| `top_k` | 控制候选词数量 |
| `num_predict` | 最大生成 token 数 |
| `repeat_penalty` | 抑制重复输出 |
| `seed` | 固定随机种子，便于复现 |
| `stop` | 设置停止序列 |

#### 推理参数怎么理解

这些参数作用于每一次请求，主要影响回答风格和输出长度，不影响模型加载方式。

- `temperature`：越低越稳，越高越发散
- `top_p`：控制采样概率范围，常和 `temperature` 一起调
- `top_k`：限制候选 token 数量，数值越小越保守
- `num_predict`：一次最多生成多少 token，想让回答更长就调高
- `repeat_penalty`：抑制重复输出，模型啰嗦时可适当提高
- `seed`：固定随机种子，便于复现结果
- `stop`：设置停止序列，遇到指定文本就截断

#### 推理参数怎么调

- 代码、配置、结构化输出：`temperature` 低一些更稳
- 创意写作、头脑风暴：`temperature` 可以适当高一点
- 模型总是重复句子：提高 `repeat_penalty`
- 输出总被截断：提高 `num_predict`
- 需要复现：固定 `seed`

#### 输出行为

如果模型支持思考过程，界面会把思考内容和最终回答分开展示。  
如果你点击停止，当前生成会立即终止，不需要等完整轮次结束。

#### 常用操作

- 直接输入问题并发送
- 生成过程中随时停止
- 观察思考内容和最终回答
- 保存常用参数预设

### 5.2 模型管理

模型管理页用于管理本地模型生命周期。

你可以：

- 拉取模型
- 查看已安装模型
- 加载模型
- 卸载模型
- 删除模型
- 设为 OpenClaw 默认模型

#### 加载模型时的参数

加载模型时可以设置：

- 上下文长度
- GPU 层数
- CPU 线程数
- 批处理大小
- mmap 等启动选项

#### 模型启动参数怎么理解

这些参数作用于“模型怎么加载”，不是“每次怎么回答”。

- `num_ctx`：上下文长度。值越大，模型可参考的历史内容越多，但也更占内存。
- `num_batch`：批处理大小。值越大通常越快，但也更吃显存和内存。
- `num_gpu`：GPU 层数。`0` 表示纯 CPU，数值越高越依赖 GPU。
- `main_gpu`：主 GPU 号。多卡场景下用于指定主卡。
- `use_mmap`：是否启用内存映射加载。大模型通常保留默认即可。
- `num_thread`：CPU 线程数。通常不建议盲目拉满。

#### 模型启动参数怎么选

- 机器内存较小，先从较小的 `num_ctx` 开始
- 显存不够时，减少 `num_gpu` 或换小模型
- 多卡机器可以优先试自动或预设方案
- 不确定怎么配时，可以直接用界面里的自动优化建议

#### 自动优化

加载窗口提供自动优化按钮。系统会结合显卡和模型规模推荐参数，通常会一起调整：

- `num_ctx`
- `num_batch`
- `num_gpu`
- `num_thread`

这适合首次加载模型，或者你不想手动估参数的时候使用。

### 5.3 模型市场

模型市场用于浏览和安装 GGUF 模型。

你可以：

- 按任务类型筛选
- 按模型大小筛选
- 按量化方式筛选
- 按下载量、名称或体积排序
- 查看模型是否已安装

安装流程通常是：

1. 在市场里找到目标模型
2. 选择量化文件
3. 点击安装
4. 等待拉取完成
5. 安装后切换到模型管理或推理页面继续使用

### 5.4 服务参数

服务参数作用在 `Ollama` 后台服务本身，也就是 `ollama serve` 进程。

| 参数 | 说明 | 常见用途 |
|---|---|---|
| `CUDA_VISIBLE_DEVICES` | 限定 Ollama 可见的 GPU | 只让 Ollama 使用指定显卡 |
| `OLLAMA_MAX_LOADED_MODELS` | 同时常驻内存的模型数量 | 经常在多个模型之间切换 |
| `OLLAMA_NUM_PARALLEL` | 并发请求数 | 提高吞吐或支持多人使用 |
| `OLLAMA_SCHED_SPREAD` | 是否在多 GPU 间分布负载 | 多卡环境做均衡调度 |

#### 服务参数怎么改

1. 打开本地推理页里的服务配置
2. 修改需要的参数
3. 保存配置
4. 重启 `Ollama` 服务

如果 `Ollama` 是应用内启动的，重启后会自动带上新配置。  
如果是外部单独启动的，需要你手动重启外部服务。

#### 服务参数怎么理解

- `CUDA_VISIBLE_DEVICES` 是“允许哪些 GPU 参与”
- `OLLAMA_MAX_LOADED_MODELS` 是“内存里常驻多少个模型”
- `OLLAMA_NUM_PARALLEL` 是“同时处理多少个请求”
- `OLLAMA_SCHED_SPREAD` 是“多卡之间怎么分摊任务”

#### 参数搭配建议

- 单卡机器：先限制可见 GPU，不要把并发开得太高
- 双卡机器：可以试试开启 `OLLAMA_SCHED_SPREAD`
- 经常切换模型：可以适当提高 `OLLAMA_MAX_LOADED_MODELS`
- 多人同时使用：再考虑提高 `OLLAMA_NUM_PARALLEL`

## 6. 技能系统

技能是 RongxinAI 的能力扩展方式。技能安装后，可以让模型在特定场景下更专业。

常见技能类型包括：

- 文档生成
- 表格处理
- 演示文稿
- 网络检索
- 前端设计
- 浏览器自动化
- 自定义技能

### 6.1 使用方式

1. 打开 `Skills`
2. 浏览已安装或市场技能
3. 启用需要的技能
4. 回到对话工作区发起任务

### 6.2 使用建议

- 任务越具体，技能调用越稳定
- 一个任务同时启用过多技能，可能会增加上下文负担
- 安装新技能前先看说明和安全提示

## 7. MCP 接入

MCP 页用于配置外部工具服务。

支持的典型配置方式：

- `stdio`
- `sse`
- `http`

你可以把它理解为给 AI 接上外部工具：

- 搜索
- 云盘
- 企业工具
- 自定义业务 API

常见操作：

- 新建服务
- 编辑服务
- 启用/禁用服务
- 删除服务
- 刷新桥接同步

## 8. 定时任务

定时任务适合做周期性工作：

- 每天汇总
- 每周报告
- 定时提醒
- 定时巡检

支持的典型配置包括：

- Cron 表达式
- 任务名称
- 执行模型
- 输出或投递目标

任务执行后，结果会通过系统内的任务流或 IM 通道返回。

## 11. 数据与安全

### 11.1 本地数据

应用的会话、配置和本地资源会存储在本机数据库和文件系统中。

### 11.2 权限边界

Electron 主进程负责系统能力，渲染进程只通过 IPC 调用功能接口。这样做的目的，是把 UI 和系统能力隔离开。

### 11.3 本地模型

如果使用 `Ollama`，推理可以完全在本地完成，适合对数据隐私要求更高的场景。

## 12. 常见问题

### 12.1 模型回复太长或上下文报错怎么办

通常是上下文长度不足，或者当前会话历史加上系统提示词太长。可以：

- 换更大的上下文配置
- 清理无关历史
- 简化系统提示词
- 重新开启一个新会话

### 12.2 本地推理没有模型列表

先确认：

- `Ollama` 是否已安装
- 服务是否已启动
- 模型目录是否正确

### 12.3 模型市场结果不多

结果数受网络、模型筛选条件和本地可用数据影响。你可以：

- 清空筛选条件重新搜索
- 打开模型详情页
- 检查网络是否能访问 ModelScope

### 12.4 对话中途想停下来

在推理或对话工作区的流式输出过程中，可以直接使用停止按钮终止生成。
